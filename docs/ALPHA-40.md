# Alpha.40: bounded party rules and agreed resume

Scope is limited to the first five approved party rules. No Gothic process is launched by the build, checks or installer.

- Observe the original first victory credit on the host. Both connected same-world players receive the full native XP, regardless of distance. Native host credit is recognized, not repeated. Unconscious recipients retain their health state after level-up. Dead recipients are not revived by an XP grant.
- Evaluate faction paths at reward grant: militia/paladin, mercenary/dragon hunter, novice/fire mage. Both players must qualify for a faction-specific reward; ordinary quests are independent of faction. The active native quest adapter is still Cavalorn, a non-faction quest. This does not claim general faction-quest detection or campaign synchronization.
- Journal the first mutating Cavalorn choice before native execution and commit afterwards. Both completion variants share one decision scope. A client may request the verified native information function; the host validates the NPC, range, readiness and native condition. Confirmation precedes the authoritative quest snapshot. Local playback is matched to the actual native reward deltas and durable receipts. Informational repeat dialogue is not permanently locked. Ambiguous interrupted native execution fails closed until a matching agreed save pair is loaded.
- Exchange bounded complete snapshots of mission-item/key permissions, without inserting duplicate items into either inventory. Shared key permission uses the existing confirmed native chest path. The verified quest context also supports a durable reservation and one debit on the actual unique-item owner, with detached native permission handles. Unsupported quest scripts do not receive these permissions. The Cavalorn bandit completion does not consume a mission item; the following Vatras quest is outside this adapter.
- Add **Union & Plugins → Orebound Co-op – Session**. After both players save normally, link their existing slots with explicit consent. Linking does not write a native game save. Loading the linked pair also requires agreement, checks all native SAV and recovery/character sidecars, and refuses pending inventory transfers or altered files. Prepared/committed plans are durable and checksummed. The transport stays responsive while files are hashed. Both loads fork fresh recovery timelines so later transactions from the discarded future are not replayed. Roles come from the agreed profiles, and repeated confirmations cannot cause another load. A committed interrupted resume can continue after restart. Failed native loads stop automatic retries. Restored guest character authority and existing owned summon identities are rebased without respawning or introducing companion behavior.

Sleep/time, general pause rules, world/chapter changes, automatic paired save writes and companion behavior are deferred. There is no resurrection feature. Ordinary NPC dialogue outside this bounded quest adapter is not converted into general shared progression.

**Protocol 13 requires both peers to update.** Ninja script ABI 2 and artwork ABI 1 remain unchanged. Transaction container format 4 now accepts new action semantics. Rollback therefore requires the matching backed-up journal/state as well as the old plugin; do not mix an Alpha.39 reader with new transactions.

Existing accepted female clothing remains unchanged. Tests cover bounded/truncated/duplicate wire data, complete resource pages, faction-path combinations, durable first decisions, one owner debit, consent gates, journal restart and real loopback UDP. Native entry bytes and the original script constants are inspected separately. Technical tests are not gameplay acceptance.
